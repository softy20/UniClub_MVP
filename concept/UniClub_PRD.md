# UniClub PRD (MVP)

## 1. 한 줄

매년 운영진이 바뀌는 대학 동아리/소모임이, 지난 운영 지식(매뉴얼·인수인계)을 넣으면 **올해 일정·D-Day 할 일·역할·회계 규칙**을 바로 운영할 수 있게 만든다.

## 2. 기획

**대학 동아리 · 소모임 오퍼레이션 자동화.**

핵심 문제는 “무엇을 하는지”가 아니라 **누가, 언제, 무엇을, 어떤 순서로 해야 하는지**가 매년 리셋되는 것이다. UniClub은 그 운영 기억을 구조화하고, 다음 기수에 넘긴다.

오션홀릭 매뉴얼(`UniClub_manual.md`)과 스키마(`UniClub_JSON.json`)는 **1개 종목의 레퍼런스 데이터**다. 제품 범위가 아니다.

## 3. 타겟과 범위

| 구분 | 내용 |
|---|---|
| 시장 | 모든 대학교 |
| 장르 | 미구분 (스포츠, 학술, 봉사, 공연, 종교, 취미 등) |
| 1순위 | **매년 운영진이 교체되는 대학 동아리** |
| 2순위 | 소모임, 학회, 학생회 산하 단체 |

1순위 유저 페르소나: 막 선출된 신임 회장/총무. 카톡방과 작년 문서만 있고, “지금 뭐부터 해야 하는지”를 모른다.

## 4. 문제 / 해결

**문제**
- 운영 지식이 카톡, 개인 메모, 구두 인수인계에 흩어져 있다.
- 기수가 바뀌면 일정·업체·D-Day·회계 수칙이 유실된다.
- 장르가 달라도 운영 루프는 같다: 모집 → 정기활동 → 큰 행사 → 정산 → 차기 인계.

**해결**
- 비정형 운영 문서 → 공통 오퍼레이션 스키마 → 임원용 운영 보드.
- 올해 운영 결과는 다음 해 입력값이 된다.

## 5. MVP에 넣는 것 / 빼는 것

### In (v1)

1. **운영 문서 입력** — 마크다운/텍스트 매뉴얼 업로드 또는 붙여넣기
2. **AI 추출** — 공통 스키마 JSON으로 변환 (실패 시 수정 가능한 초안)
3. **연간/월간 타임라인** — 이번 달 핵심 테마와 주차별 할 일
4. **행사 + D-Day 태스크 보드** — 역할별, 필수/선택, 체크리스트
5. **회계·행정 규칙 조회** — 회비, 면제, 영수증 증빙 (결제 기능 아님)
6. **행사별 준비물 리스트**

### Out (v1에서 명시적으로 안 함)

- 카카오톡/에브리타임 연동, 투표, 정산 송금
- 출석, 활동일지, 회원 DB, 로그인 고도화
- 회비 결제, 지원금 보고서 자동 작성
- 종목별 커리큘럼 엔진 (스쿠버 OW 회차 등)
- 일반 부원용 SNS/피드

## 6. 핵심 시나리오

1. **신임 회장**: 작년 인수인계 문서를 넣는다 → 3월 신입모집부터 12월 인선까지 월별 보드가 생긴다.
2. **총무**: 다가오는 큰 행사에서 D-14 필수 할 일(예약, 보험, 정산 증빙)을 확인한다.
3. **차기 인계**: 올해 수정된 일정/수칙을 다시 문서로 보낸다. (내보내기는 v1 후순위여도, 데이터는 남긴다.)

## 7. 데이터 계약 (스키마 방향)

현재 `UniClub_JSON.json`은 오션홀릭에 고정된 enum이 많다. 제품 스키마는 **공통 코어 + 동아리별 커스텀 값**으로 바꿔야 한다.

**공통 코어 (장르 무관)**
- `club_info`: 이름, 학년도, 자문/지도, 소통 채널 규칙
- `events[]`: 행사명, 카테고리, 시기, 장소, 1인 비용, `tasks[]`
- `tasks[]`: 할 일, D-Day 역산, 담당 역할, 필수 여부, 체크리스트
- `financial_and_admin_rules`: 회비, 면제, 증빙 규칙
- `monthly_timelines`: 월 테마 + 주차 마일스톤
- `packing_lists`: 행사 유형별 준비물
- `gifts_and_anniversaries`, `booth_and_promotions`, `equipment_group_buys` (있으면 추출, 없으면 빈 배열)

**동아리가 정하는 값 (하드코딩 enum 금지)**
- 역할: 회장/총무/훈련부 대신 `roles[]` (동아리가 정의)
- 행사 카테고리: 해양훈련 대신 자유 문자열 또는 클럽 커스텀 enum
- 준비물 행사 유형: `빠지_MT` 같은 고정값 제거

**레퍼런스 전용 (오션홀릭 예시, 제품 필수 아님)**
- `training_curriculum` (OW/AOW 회차)
- 자격증 비용 `OW/AOW/DM`
- 스쿠버 안전 브리핑, 특정 샵/수영장명

v1 추출기는 오션홀릭 매뉴얼로 품질을 검증하되, **다른 장르 매뉴얼이 들어와도 코어 필드가 채워져야** 한다.

## 8. 런타임 (스키마 밖에 필요한 것)

추출 결과만으로는 운영이 안 된다. v1에서 최소로 둔다.

- 행사 실제 날짜(`event_date`) — 있으면 D-Day 계산, 없으면 월/주차만 표시
- 태스크 상태: 미완 / 완료
- 역할 단위 필터 (사람 계정은 나중에)
- 추출 실패·누락 필드 하이라이트 후 직접 수정

로그인·알림·개인 담당자 배정은 v1.1 이후.

## 9. 성공 기준 (MVP)

- 오션홀릭 매뉴얼 1건 → 코어 스키마가 빠짐없이 채워진다.
- 장르가 다른 매뉴얼 1건(예: 밴드, 봉사, 학술) → 행사/할 일/월간 타임라인은 추출된다. 종목 전용 필드는 비어도 된다.
- 신임 임원이 **이번 달 “지금 할 일”**을 3클릭 안에 본다.
- 하드코딩된 스쿠버 용어 없이도 보드가 동작한다.

## 10. 열린 결정 (권장 기본값)

| 항목 | 권장 |
|---|---|
| 1차 검증 데이터 | 오션홀릭 매뉴얼 (이미 있음) |
| 2차 검증 데이터 | 장르가 다른 짧은 인수인계 1건 |
| 권한 | v1은 임원 단일 보드 (부원 화면 없음) |
| 배포 | 웹 MVP (캠프/데모용) |
| 카톡 대체 | 하지 않음. 보드는 운영 소스, 공지는 기존 채널 |
